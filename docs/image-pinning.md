# Image Pinning Policy — Tags → Digests

Pinned source: `meridian-core-platform @ c31c8e93fdce7e0e742609c7e0d8ba082a5fa711`
(policy added on branch `fix/assurance-r5`).

## Why

All production middleware images in `infra/docker-compose.prod.yml` and
`infra/helm/values-prod.yaml` were referenced by **mutable tags**
(`postgres:16-alpine`, `bitnami/etcd:3.5`, `apache/apisix:3.9.0-debian`,
…). A tag can be re-pointed by the registry/publisher, so two deploys of "the
same version" can run different bytes — a supply-chain and reproducibility
gap.

## Policy

1. **Production deploys MUST run digest-pinned images.** A digest
   (`repo@sha256:…`) is immutable content addressing.
2. **Digests are resolved, never invented.** No digest value may be typed by
   hand or generated by tooling other than a live registry resolution
   (`crane digest`, `skopeo inspect`, or `docker pull` + `inspect`). A digest
   that was not resolved from the registry at pin time is worthless and
   forbidden — including in this repo's docs and templates.
3. **The repo keeps tags as defaults.** Compose uses the
   `${IMG_*:-<tag>}` pattern so dev flows are unchanged; prod overrides come
   from `.env.prod`.
4. **Re-pin on every upgrade and at least monthly** (tags drift: security
   rebuilds move `*-alpine` and `x.y` tags).

## How: docker-compose (implemented)

1. `infra/docker-compose.prod.yml` now declares every image as
   `image: ${IMG_<NAME>:-<current tag>}` (20 variables).
2. Resolve and generate the pin file:
   ```sh
   scripts/pin-images.sh            # writes .env.prod.digests
   ```
   Tool resolution order: `crane` → `skopeo` → `docker`. Any tag that fails
   resolution is emitted **commented out** with an `UNRESOLVED` marker and
   the script exits 1 — never uncomment such a line with a guessed value.
3. Merge `.env.prod.digests` into `.env.prod` (section pre-staged in
   `.env.prod.template`). Deploy as before:
   ```sh
   docker compose --env-file .env.prod -f infra/docker-compose.prod.yml up -d
   ```
4. Record the pin file (or its sha256) as deploy evidence via
   `POST /v1/evidence` (audit-evidence service).

## How: helm

`infra/helm/values-prod.yaml` image fields are plain strings
(`workloads.tigerbeetle.image`, `workloads.temporalWorker.image`,
`observability.{prometheus,alertmanager,grafana}.image`). To pin:

```sh
crane digest ghcr.io/tigerbeetle/tigerbeetle:0.16.4
# set in values-prod.yaml:
#   image: ghcr.io/tigerbeetle/tigerbeetle@sha256:<resolved>
```

Helm values accept `repo@sha256:…` directly; no template change is needed.
The same resolve-only rule applies.

## Verification

- `docker compose --env-file .env.prod -f infra/docker-compose.prod.yml config | grep 'image:'`
  — every prod service must show `@sha256:`.
- CI/fail-safe: if `IMG_*` is unset, compose renders the tag default — treat
  any tag-rendered image in a prod render as a policy violation.
